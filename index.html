01背景与目标

运营一个微信公众号的日常成本主要在两块：写（每天要有内容产出）和发（到点要记得发）。这两件事都是重复劳动，且高度依赖人的记性。

本项目要把这条链路自动化：每天定时跑一次，自动完成选题、成稿、排版、配图，推给运营者确认，确认后自动发布。

1.1 目标

  • G1 每日自动出稿：无需人工介入即可产出可发布的成稿，运营者每天的工作从「写」降为「审」。
  • G2 定时发布：支持指定时间自动发布，也可人工确认后立即发。
  • G3 公众号格式原生适配：产出的排版在公众号编辑器里直接可用，不需要人工二次调格式。
  • G4 权限降级不降级体验：账号权限不足时自动降级为「存草稿 + 人工点发表」，功能不中断。

1.2 非目标

  • 不做多账号矩阵管理（先单号跑通）。
  • 不做粉丝运营（自动回复、用户画像、菜单管理）。
  • 不做内容爬虫农场（选题来源以配置化栏目为主，不做大规模抓取）。
  • 不做全自动无人审核发布（见第 10 章合规说明）。

02硬约束（方案的前提）

这一章是整个方案的地基。下面每一条都直接决定了架构长什么样，不是背景介绍，请先读完再往下看设计。

2.1 微信平台规则约束

最关键的一条：发布接口的权限门槛

微信自 2025 年 7 月起收紧了发布接口权限——个人主体账号、未认证的企业账号会被回收 freepublish/*（发布）与 mass/*（群发）接口的调用权限，调用会返回 48001（无该接口权限）。草稿接口（draft/*）通常仍然可用。

这意味着：如果本号未认证，程序能自动做到「生成 + 存草稿」，最后一步「发表」必须人工点。本方案据此把发布器设计成可插拔的（见 6.6），权限到位后改一行配置即可全自动。

约束说明对设计的影响
发布 vs 群发 群发（mass/sendall）：粉丝收到推送通知，占用群发额度。发布（freepublish/submit）：不推送通知、不占群发额度、生成永久链接，内容挂在号上。 「每日发」必须走发布而非群发
群发次数上限 订阅号 每天 1 次；服务号 每月 4 次。 即使走群发，服务号也做不到每日
IP 白名单 调用 API 的服务器出口 IP 必须加入公众号后台白名单，否则报 40164。 需固定出口 IP，见 6.2
access_token 有效期 7200 秒；同一账号多进程并发刷新会互相顶掉，导致间歇性 40001。 必须中控缓存，见 6.1
正文图片外链 正文中直接引用外部图片 URL 会被微信屏蔽（防盗链），在公众号里不显示。 图片必须先上传素材，见 6.4
编辑器样式 公众号编辑器只认内联样式；<style> 标签与 class 基本无效。 排版层直接产出内联 style，见 5.3

2.2 运行环境约束

项目实测结果应对
Python 版本仅 3.6.8，无其它版本不使用 3.7+ 语法（dataclass、海象运算符等）
第三方库requests / Pillow / jinja2 均未安装纯标准库实现，零依赖
系统环境CentOS 7 系（内核 3.10 / glibc 2.17）不依赖新版 OpenSSL，不装重编译包
外网连通性微信 API ✅、PyPI ✅、通用外网 ✅可直接调用微信接口
出口公网 IP111.228.14.136填入微信后台 IP 白名单
零依赖是个好约束，不是妥协

本项目要做的事（HTTP 调用、JSON 处理、字符串模板、定时、SQLite 状态）标准库全部覆盖：urllib.request 替代 requests、json、sqlite3、html、hashlib、hmac。好处是换任何机器都能直接跑，没有装包这一步就没有装包失败——考虑到本机 Python 3.6 的生态现状，这反而是最稳的选择。

03产品方案

3.1 每日工作流

运营者每天只有两个动作：早上点一下确认，其余全自动。

07:00
定时任务触发，从配置的栏目里选题（或用前一日的选题池）
07:00 – 07:05
调用大模型生成正文，生成/选取配图，上传图片到微信素材库
07:05
排版：Markdown → 公众号内联样式 HTML，渲染出本地预览页
07:06
推送飞书审核卡片给运营者：标题、摘要、预览链接、[批准发布] / [驳回] / [改写] 按钮
08:00 前
运营者看卡片，点批准（或什么都不做，按配置走默认策略）
08:00
发布：生成草稿并提交发布（权限不足则存草稿并通知运营者手动发表）

05核心模块设计

5.1 选题模块

选题是内容质量的上限。MVP 阶段采用配置化栏目 + 选题池，不做大规模抓取：

  • 配置里定义若干栏目（如「行业观察」「工具推荐」「每周复盘」），每个栏目带提示词倾向与配图风格。
  • 每日按配置的轮换策略选栏目（轮询 / 权重），再从栏目下的选题池取一条。
  • 选题池支持人工补充（运营者往 JSON 里加），也支持程序按提示词让模型先生成候选再选。
  • 去重：近 N 天已用过的选题标记为已用，避免重复。

5.2 生成模块

  • 输入：选题 + 栏目提示词 + 文风约束 → 输出结构化结果 {title, digest, body_markdown, cover_prompt}。
  • 要求模型输出 JSON而非自由文本，便于程序解析；解析失败时降级为「整段当正文 + 首行当标题」。
  • 模型来源可切换：Claude API（推荐，写作质量最好）或自建 vLLM 服务（成本低、数据不出内网）。注意：自建的 dh 系列是聊天场景微调的，写推文效果不佳，需另训或不用。
  • 生成结果落库，保留原始响应以便排查。

5.3 排版模块（关键）

这里的坑：公众号不吃外部 CSS

公众号编辑器会剥掉 <style> 标签和 class 属性。所有样式必须内联写在每个标签的 style="" 里。所以不能直接用通用的 Markdown→HTML 库，必须自己控制输出。

  • 输入 Markdown（受限子集：标题、段落、加粗、引用、列表、代码块、图片），输出全内联样式的 HTML 片段。
  • 只支持公众号认得的标签：section / p / span / strong / h / img / blockquote / ul。
  • 主题模板：一套配色与间距常量（字号、行高、主色、引用块样式），换主题只改常量。
  • 产出两份：一份给微信的 content 字段，一份包上手机外框的本地预览页（供审核时看效果）。
# 排版输出示意：每一处样式都内联
<section style="font-size:16px;line-height:1.75;color:#333;">
  <p style="margin:0 0 16px;text-align:justify;">正文段落…</p>
  <blockquote style="margin:16px 0;padding:12px 16px;border-left:3px solid #2C4A8C;background:#F3F4F7;color:#555;">
    引用内容
  </blockquote>
</section>

5.4 素材模块

  • 封面图：MVP 用模板图（本地生成一张带标题文字的图）或从图库选，通过 material/add_material 上传为永久素材，拿到 media_id。
  • 正文图：通过 media/uploadimg 上传，返回 mmbiz.qpic.cn 地址，用它替换正文里的原始图片地址。
  • 本机禁用无头浏览器（glibc 2.17，Chromium 跑不起来），所以不做 HTML 截图生成封面；封面走「模板图 + 文字叠加」或外部图片生成 API。
  • 上传结果与 media_id 缓存进状态库，避免重复上传（素材有数量上限）。

5.5 审核模块

  • 生成完成后推一张飞书交互卡片：标题、摘要、预览链接、三个按钮（批准发布 / 驳回 / 改写）。
  • 批准 → 触发发布；驳回 → 记录原因，当日不发；改写 → 带意见重新生成一版再推卡片。
  • 超时未响应按配置处理：默认不自动发布（内容风险不可逆），仅提醒。
  • 复用本机已有的飞书能力，不重复造。

5.6 发布模块（可插拔）

定义统一的发布器接口，三种实现，按账号权限自动选择：

发布器调用接口行为前提
FreePublisherfreepublish/submit提交发布，生成永久链接，不推送粉丝已认证账号
MassPublishermass/sendall群发，粉丝收到推送（受次数限制）已认证 + 有额度
DraftPublisherdraft/add只存草稿，通知运营者到后台手动发表无门槛（兜底）
# 发布器接口（示意）
class Publisher(object):
    def publish(self, article):
        """提交内容，返回 PublishResult(status, media_id/url, message)"""
        raise NotImplementedError

# 选择逻辑：探测权限 → 选发布器 → 失败自动降级
publisher = FreePublisher(wx) if has_perm("freepublish") else DraftPublisher(wx)
result = publisher.publish(article)
if result.errcode == 48001:          # 权限不足，降级重试
    result = DraftPublisher(wx).publish(article)

图 5-1 发布器抽象。权限探测失败或调用返回 48001 时自动降级为草稿，功能不中断。

06微信集成层设计

6.1 access_token 中控

最容易踩的坑：token 互相顶掉

同一账号的 access_token 是全局唯一的——新获取的会让旧的立即失效。如果有两个进程（或两个定时任务重叠）同时去刷新，就会互相顶掉，表现为间歇性 40001 报错，且极难复现和排查。

  • token 统一由 wx/token.py 管理，所有需要 token 的调用都必须从这里取，不允许各模块自己拉。
  • 缓存落地为文件（workspace/token.json），带 过期时间 + 提前刷新窗口（到期前 5 分钟才刷新）。
  • 刷新加文件锁，保证同一时刻只有一个进程真正发起刷新请求，其余进程等待复用结果。
  • 刷新失败时使用旧 token 重试一次再报错，避免瞬时网络抖动导致整批任务失败。

6.2 IP 白名单

  • 本机出口 IP 实测为 111.228.14.136，需加入公众号后台「设置与开发 → 基本配置 → IP 白名单」。
  • 风险：该 IP 是动态分配的话会漂移，届时所有 API 调用报 40164。程序启动时做一次白名单自检（调一个轻量接口如 get_api_domain_ip 或 token 接口），失败即告警，而不是等到发布时才发现。
  • 若 IP 不稳定，方案是把调用收敛到一个固定出口的机器上当网关（见 12 章开放问题）。

6.3 错误码处理

错误码含义处理策略
40001凭证无效强制刷新 token 后重试一次；仍失败则告警
40164IP 不在白名单立即告警（改配置才能修），当日任务转草稿模式或停止
48001无该接口权限触发发布器降级（Free→Draft），并记录账号权限画像
45009接口调用额度超限退避重试，跨日重置
45011频率过高指数退避重试
-1系统繁忙重试 3 次，退避 2s/4s/8s

6.4 HTTP 客户端

  • 基于 urllib.request 封装，统一处理：超时（默认 10s）、重试、JSON 解析、错误码提取。
  • 上传素材是 multipart/form-data，urllib 不直接支持，需手写 multipart body——这是本项目唯一需要点技巧的地方，独立成函数并配单元测试。
  • 所有请求记录耗时与结果到日志，便于排查。

07数据模型

用 SQLite（标准库自带），单文件，够用且无运维成本。

08部署与运行

8.1 运行方式

# 手动跑一次全流程
python3.6 run.py run

# 只生成 + 出本地预览，不推审核、不发布
python3.6 run.py preview

# 对已生成的稿子重新提交发布
python3.6 run.py publish --article-id 42

# 常驻模式：内部调度，每天 07:00 触发
python3.6 run.py daemon

8.2 调度

  • 推荐外部 cron 触发（更可靠、日志更好管）：0 7 * * * cd /path && python3.6 run.py run。
  • 本机的 metabot 调度也能承担这一步，无需额外装 crontab。
  • daemon 模式仅作为备选，内部 sleep 循环对时钟漂移不友好。

8.3 目录与产物

  • workspace/preview/YYYY-MM-DD.html — 每日预览页
  • workspace/images/ — 配图与封面
  • workspace/logs/YYYY-MM-DD.log — 运行日志
  • state.db — SQLite 状态库（不入库）

10安全与合规

两条必须守住的线

1. AI 生成内容标识。据我所知《人工智能生成合成内容标识办法》已于 2025 年 9 月生效，要求 AI 生成的图文内容添加标识。发布前请确认当前具体要求，在文末加注「本文由 AI 辅助生成」之类的说明是成本最低的做法。

2. 不默认全自动发布。AI 写的内容一旦发布不可逆（可能被转发、被收录）。本方案默认人工确认后才发，超时未确认不自动发。「全自动」是可配置的选项，不是默认行为。

10.1 密钥与凭证

  • AppSecret、LLM API Key 只从环境变量读，配置文件里是占位符。
  • config.json / state.db / workspace/ 全部加入 .gitignore。
  • token 缓存文件权限设为 600。

10.2 内容安全

  • 生成结果入库留痕（llm_calls），可追溯每篇稿子由哪个模型、什么提示词产出。
  • 可配置敏感词前置检查，命中则拦下不推审核卡（P2）。
  • 发布失败不重试超过 N 次，避免刷接口触发风控。

12风险与开放问题

12.1 风险

风险等级应对
账号未认证，发布接口不可用高默认走草稿模式；发布器可插拔，认证后改配置即升级
出口 IP 漂移导致 40164高启动自检 + 告警；必要时收敛到固定 IP 网关
AI 生成内容合规标识中默认加 AI 标识；发布前确认最新要求
生成质量不稳定中人在环审核 + 支持驳回改写；积累提示词模板
公众号编辑器样式兼容中只用安全标签 + 全内联样式；每次变更后在手机上实测

Q4 用哪个模型

本机跑不了无头浏览器，不能 HTML 截图。选项：模板图+文字、图库选图、或接图片生成 API。
